# D — own Dienste (group planner, PEP lock)

Planner creates only its own codes (`PSP-*`), never flips a seed Dienst (definitions are global: every group on the box reads them). Run after UTR's Phase 1 PEP part (shared desktop), each PEP action under `locks/<env>~pep` (≤ 20 min holds, renew).

| Step | Dienst                            | Flags                                                                                                                                                                                                                                       | Used by |
| ---- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| D1   | `PSP-IP-JA` (presence)            | `DIENST.INTERNER_POOL = 'T'`, `RESSOURCENERSATZ = 'F'` (master line; on main-26 only `RESSOURCENERSATZ`)                                                                                                                                    | PSP-20  |
| D1   | `PSP-IP-NEIN` (presence)          | `INTERNER_POOL = 'F'`, `RESSOURCENERSATZ = 'T'`                                                                                                                                                                                             | PSP-20  |

| D3   | `PSP-WUNSCH-JA` (presence)        | `DIENST.PLANUNGSWUNSCH = 'T'` and, on the G-A `DIENST_DETAIL` row covering DW, `PLANUNGSWUNSCH = 'T'` (+ `PW_ROLLE_ID` as PEP writes it: prefer the PEP tab "Dienstmodifikation → Detail… → Planungswunsch → für Planungswunsch verfügbar") | PSP-22  |
| D3   | `PSP-WUNSCH-NODE-NEIN` (presence) | only `DIENST.PLANUNGSWUNSCH = 'T'`                                                                                                                                                                                                          | PSP-22  |

1. Create each Dienst in PEP with the Dienst wizard (utr seed README step c pattern: Dienst dialog, title, times, presence type), add it to G-A's palette, and make PEP know the code on the root node (R0 root rows are the steward's; the new code needs the same root-node treatment — follow the UTR seed README step j pattern for the new PA codes only). Screenshots per dialog.
2. Flags: preferably in PEP's Dienst dialog tabs ("Interner Pool", "immer sichtbar", "Planungswunsch") — no pep-driver flow exists (OQ-20): exploratory pep-verify. SQL alternative on **your new codes only**: `UPDATE ECBERN.DIENST SET INTERNER_POOL='T', RESSOURCENERSATZ='F' WHERE PA_CODE = <PSP-IP-JA>;` etc. + `COMMIT` (columns per `ShiftDefinitionEntity.java:70-83`).
3. One G4b batch (one PL/SQL block + COMMIT): a batch file with the lines `shift-definition <the five codes>`, `policy-of <the five codes>`, `palette <G-A node>` → `scripts/psc-enqueue.sh <env> --batch <file>` (pattern of `scripts/seed/common/psc-batch.sql`).
4. **Gate PSP-GD:** `planner-checks.sql` C2a / C2b / C3 / C4 show the flags and palette entries; as SPA `GET /api/private/shift-definition/roster?group-node-id=<G-A>&from=<D1>&to=<D1>&include-presences=true&shift-type-filter=USE_IN_PLANNING` lists the five codes; as HP7 `GET /api/mobile/health-professional/v1/scheduling-requests/shift-definitions?…<DW>` lists `PSP-WUNSCH-JA` and not `PSP-WUNSCH-NODE-NEIN`. A 404 "Shift definition … not found" = G4b not effective: re-enqueue once, else tell the steward.
5. Write the PA codes into the run config placeholders `DEF_IP_JA`, `DEF_IP_NEIN`, `DEF_IMMER`, `DEF_WUNSCH_JA`, `DEF_WUNSCH_NEIN`; log them in `created/seed.jsonl`.
