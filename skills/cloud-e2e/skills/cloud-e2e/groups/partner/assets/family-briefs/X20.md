## PTN-20 — Provider error strategies for booking and cancellation

1. `gwmock.mjs … strategy get` → `strategies-before.json`; both must be `SUCCESS` (else stop: BLOCKED "mock not in SUCCESS before the window", report the values — another team may be using it).
2. Simulator as SPX: HP C rows `{{XD9}}` EARLY and `{{XD10}}` EARLY (no pool, GLN `{{GLN}}`).
3. Take `locks/ct~gwmock`; `strategy set booking CONFLICT`. BADI external (`/badi?group-node-id={{SPX_NODE}}&range-start={{XD9}}&cell-width=60&number-of-cells-displayed=14&employee-column-width=220`, toggle "Externe Pools"): book HP C `{{XD9}}` → dialog "Buchung abgelehnt" ("Die Buchung wurde vom Personalverleiher abgelehnt.", reason shown) → shot `03-rejected.png`; capture the POST.
4. `strategy set booking GENERIC_ERROR` → book HP C `{{XD10}}` → the same dialog family (shot); `strategy set booking HTTP_500` → book `{{XD10}}` again → error dialog (shot).
5. **Restore** `strategy set booking SUCCESS`.
6. `strategy set cancel DEADLINE_PASSED`; external-pool tab (`/shift-planner/manage-shift-bookings/external-pool`): cancel the `{{XD3}}` booking → dialog "Partner nicht informiert" (shot `06-not-notified.png`); capture the DELETE.
7. **Restore** `strategy set cancel SUCCESS`; `strategy get` → `strategies-after.json` = SUCCESS / SUCCESS. Delete the lock (pinned). Steps 5 and 7 run even when an earlier step failed.
8. Oracles: `GET /api/private/external-providers/transactions?…` → `transactions.json`; `gwmock.mjs … received --tx <ids of steps 3, 4, 6>` → `received-bookings.json`; `ext-planning.sql` for `{{XD3}}`, `{{XD9}}`, `{{XD10}}`.

Expect: 3 / 4 → no transaction recorded, no external planning, the availability still bookable; received bookings show `REJECTED_CONFLICT` / `REJECTED_GENERIC_ERROR` / `FAILED_HTTP_500`. 6 → transaction `CANCELLED_PROVIDER_NOT_NOTIFIED`, PEP planning of `{{XD3}}` deleted, the received booking shows the refused cancellation (`lastCancellationRefusal = DEADLINE_PASSED`) and stays "Booked" on the partner side. 7 → both strategies SUCCESS.
