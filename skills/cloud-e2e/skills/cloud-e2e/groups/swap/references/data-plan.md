## 3. Group seed (R2, runner) — order

1. **S1 pick people** (`seed/S1-pick.md`) → `swap-allocation.md`, claims.
2. **S3 membership** (`seed/S3-membership.md`, core `scripts/seed/common/kit-member.sql`): T10 → `E2E:HP-NOSWAP` (leaves the seed groups that grant 200005, `verify-kits.sql` K9; also `PEP - Leitbediener` when its gate still shows the right; keeps `DMSEED:Planner` for the mobile rights), SP → `E2E:SP-ALL` (keeps `DMSEED:Planner`); the script enqueues `PERMISSION_GROUP_MAPPING`; re-login check.
3. **S5 absences and on-call / S6 halves** (`seed/S5-S6-paints.md`): `pp-plan.sh` per cell of `seed/paint-plan.tsv` (api-pp `direct-shift-planning`, verified once per env by the steward in S1); PEP fallback `pe-paint.sh` under `locks/<env>~pep` (full cells only; half cells without `pp-plan.sh` → family E BLOCKED).
4. **S7 conflict candidate** (`seed/S7-conflict.md`): find or build one WARNING/FORBIDDEN conflict for T4 on D1; record `{{CONFLICT_RECIPE}}`.
5. **S8 verify + gates** (`seed/S8-verify-gates.md`): `plan-day.sh` for every allocated cell; one login per actor; gates G-SWP-DEF, G-SWP-ROLES, G-SWP-HALF, G-SWP-EVT.

Estimated ≈ 90 min with `pp-plan.sh`, ≈ 180 min with PEP paints.

## 4. Concurrency

| Shared state                           | Mutated by                                                          | Effect on others                                                                         | Rule                                                                       |
| -------------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

| `nodeBasedApprovers` (baseline ON)     | —                                                                   | every holder of 1070 (all seed logins) gets SUBMISSION notifications                     | notification assertions filter by opportunity id + time                    |
| Rosters of the allocated cells         | approvals (SWP-11, 13, 18, 27), PEP changes (family D), seed paints | candidate lists of the same Gruppe and day                                               | the group owns its cells; other groups never use T / U people              |
| Locks (user × day)                     | swap creation / YES                                                 | `USER_IS_LOCKED` across flows (RR / IPO of other groups use other people)                | allocation 2.3 is the lock plan; every scenario cancels its own open swaps |
| SP marketplace list                    | every swap scenario                                                 | SWP-15 assertions                                                                        | assert by opportunity id, never by counts                                  |
| Run partner (stage-wide)               | steward only                                                        | SWP-31, BKG-27, partner                                                                  | read only; any save wipes the Debug log                                    |
| PEP desktop (one per box)              | family D, S5–S7 fallback, SWP-13/29 conflict step                   | every PEP user of DM-X                                                                   | `locks/<env>~pep` ≤ 20 min holds; prefer `pp-plan.sh`                      |

**Inside the group.** Three lanes on disjoint (person, day) cells: L1 = B → D, L2 = A → C, L3 = E; F after the lanes; X03 / X07 / X14 in their windows. A T person may be driven by two workers at the same time only on different days and in different browser profiles (cell-level ownership; see group brief "Logins"). SWP-01 runs first: the other lanes start when SWP-01 is PASS.

- No OPEN / SUBMITTED swap of a T / U person (SP list "Offene Anfragen" filtered by these people is empty).
- Flags at baseline after every window (restore proof in `windows/<env>~<id>`).
- Reused env only: restore the repainted cells (re-run the paint plan), T10 back into `DMSEED:Planner`.
- The run partner is the steward's: nothing to clean here.
