**PENDING convention.** Part 1 reports OPS-13 `PENDING` with the part-A results; part 2 reads them and reports the final verdict.

Send Messages check before every press of "Send test message": `portal-ops.mjs {{PORTAL_PROFILE}} "tenant read {{TENANT}}" <out>` → `send_messages`. You never toggle it.

## Part 1 (Send Messages OFF)

1. `section('{{PORTAL_ORG}}', '{{TENANT}}', 'diagnostics')` → "Test Send Messages": text "The default SMS number will send an SMS to a test number…" with the sms-logger link (record the `href`); the Mobile number field is pre-filled (masked in shots). Shot `01-panel.png`.
2. `send_messages` must be `false` (else stop: BLOCKED "Send Messages already ON"). Press "Send test message" → `POST /tenants/{{TENANT}}/diagnostics/messaging/sms?recipient=…` → **403**, body "SMS messages are disabled for this tenant"; alert "Error sending message: …" (in `dialogs.log`) → `sms-403.json`. No SMS is sent (the check runs before api-gw).
   Report `PENDING`; the runner tells the steward that part 1 is done.

## Part 2 (Send Messages ON, switched by the steward)

3. Poll `tenant read` every 60 s (≤ 30 min) until `send_messages` = `true` → `tenant-on.json`; never later than the window.
4. Diagnostics → "Send test message" (number untouched) → 200 "SMS message sent, verify that it arrived"; alert "Message sent, check your phone for the message" → `sms-200.json`.
5. Oracle: the operator checks the sms-logger page (host from OPS-G5) for a new message to the test number within 2 min and writes the time and the first 20 characters into `notes.md` (the harness never opens the sms-logger).
6. Do not switch anything off: report; the steward switches Send Messages OFF and verifies it after the last item of the window.

Expect: part 1 → 403 with the exact text and no send; part 2 → 200 and one logged SMS.

## Cleanup checklist

- Exactly one SMS sent (part 2); no number changed; Send Messages state left to the steward.
