## OPS-18 — Job management: safe job runs with a metrics oracle

1. `/ops/monitor` → for Poma API, Poma Core, Poma Conflict Checker, Portal API, Portal Core, Portal Monitor, Portal Events, Event Handler, Messaging, PolyId Login: Aspect "Job Management" → job names (`jobs-<service>.json`, or `job list <service>`). For Tenant Access, Poma Webapp, Skill Catalog Core, CPP API, CPP, IPSP: no table and no error alert (PPCLOUD-12698).
2. Per job to run: read the baseline sums of `polypoint.job.task.executed` and `polypoint.job.task.unrecoverable.errors` for its `class` tag (values from the metric's `availableTags`) on **every pod** → `metrics-before-<job>.json`.
3. Run the Tier A jobs one at a time (`job run … --window S-CT-JOBS`), then the Tier T job with `--tenant {{TENANT}}`; each POST → 200 (`job-run-<job>.json`). A refusal by the helper's allow-list = stop that job (never work around it).
4. After each run poll the metrics (≤ 3 min): executed sum increased, unrecoverable sum not → `metrics-after-<job>.json`. `LoadTenantVersions`: `GET /versions/tenants` → `{{TENANT}}`'s `last_update` advanced (`versions-*.json`).
5. Record the UI feedback after "Execute" in the Monitor UI for one Tier A job: none besides the closed dialog = **OPS-S5** (observation, not a FAIL).

Expect: jobs listed per service; every allow-listed job executes without unrecoverable errors.
