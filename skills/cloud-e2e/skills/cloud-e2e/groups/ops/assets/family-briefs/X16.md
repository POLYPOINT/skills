## OPS-16 — Cloud monitoring: threads, logging level (with restore), database, metrics, generic, extras

1. Service "Poma Core" → Aspect "Threads" → "Single" → Select Pod (first) → thread select → stack trace shown; the threaddump has ≥ 1 thread → `threads-names.json`. Shot `01-threads.png`.
2. Aspect "Logging Level": default "Configured"; Sort by "Name" → alphabetical except ROOT; search `actuate` → "Effective" shows more than "Configured"; search `endpoint.jmx` → "Configured" none → "All" ≥ 1.
3. Record the current configured / effective level of `org.springframework.boot.actuate.endpoint.jmx` on every pod (`pods('<poma-core service>')` + `actuator(…, 'loggers/org.springframework.boot.actuate.endpoint.jmx')`) → `loggers-before.json`. Set it to TRACE in the UI → reload → reselect Poma Core / Logging Level → TRACE "(configured)"; per pod `configuredLevel` TRACE → `loggers-trace.json`. **Restore within 5 min**: set the recorded level (INFO, or the effective level when none was configured) → every pod back → `loggers-after.json`. A missing restore is a FAIL; the restore runs even if a check failed.
4. Aspect "Database" → "JDBC Metrics / JDBC Active vs Idle" chart per pod within 30 s. Shot `04-db.png`.
5. Aspect "Metrics" → Select Pod → Endpoint `hikari.connections.usage` → JSON → tick COUNT → chart within 30 s. Shot `05-metrics.png`.
6. Aspect "Generic" → Select Pod → Endpoint `health` → JSON with `status` → `health.json`. Optional: Service "Messaging" → Generic → `deephealthcheck` → record the "SMS Sending Service" status.
7. Extras, load only: Poma Core "Notifications" (dead-letter queues), "Execution Metrics"; Portal Core "VPN"; any service "Cache Management" (**never** clear).

Expect: every aspect renders data; the logger change applied to all pods and restored. The runner copies `loggers-after.json` into the window doc as the restore proof.
