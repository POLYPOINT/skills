## Steps per scenario (same skeleton for every row; the scenario-specific checks are in the table)

1. Write `{{RUN_DIR}}/scripts/R-read.mjs` once:
   ```js
   import { day, readDay, summary, save, expand, stepper, UTR } from '{{GROUP_DIR}}/scripts/harness/utr-lib.mjs';
   export default async (ctx) => {
     const { page, api, shot, log, out } = ctx;
     const { steps, step } = stepper(log);
     for (const d of (process.env.DAYS || '').split(',')) {
       const r = await day(ctx, d);
       await expand(page);
       await shot(`day-${d}`);
       save(out, `days-${d}.json`, r?.body);
       const plan = Array.isArray(r?.body) ? r.body[0] : null;
       const perm = await api.get(`${UTR}/permissions?date=${d}&employment-id=${plan?.employment_id}`);
       save(out, `permissions-${d}.json`, perm);
       step(d, {
         status: r?.status,
         sum: summary(plan),
         mode: perm.body?.time_recording_mode,
         benefits: plan?.benefits,
       });
     }
     return steps;
   };
   ```
2. Run it per employee and scenario (one login at a time; R-07 additionally reads `GET /reports/month` for E4's month — add it to your script or reuse the M-02 capture):
   ```
   cd {{RUN_DIR}} && MYPP_PROFILES={{RUN_DIR}}/.profiles/R DAYS={{P0}},{{P1}} \
     node {{SKILL_DIR}}/scripts/harness/mypp.mjs {{TENANT}} {{E1_LOGIN}} scripts/R-read.mjs R/R-01
   ```
   R-02 `DAYS={{KOMBI_DAY}}` as `{{KOMBI_EMP}}` → `R/R-02`; R-04 `DAYS={{CARVE_DAY}}` as `{{CARVE_EMP}}` → `R/R-04`; R-03 `DAYS={{P1}}` as E2 → `R/R-03`; R-05 `DAYS={{P1}},{{P3}}` as E3 → `R/R-05`; R-06 `DAYS={{P2}}` as E3 → `R/R-06`; R-07 `DAYS={{P1}}` as E4 → `R/R-07`; R-08 `DAYS={{P3}},<P3+1>` as E1 → `R/R-08`; R-10 and R-12 `DAYS={{P2}}` as E1 → `R/R-10` (R-12 points to the same evidence); R-09 reuse the R-08 / R-07 captures (`benefits`); the E6 evidence `DAYS=<E6's first planned day>` as E6 → `R/R-11/e6` and add `api.get('/api/mobile/legacy-time-recording/v1/permissions')` (evidence only, no verdict).
3. DB check for every row: `{{GROUP_DIR}}/scripts/oracle-day.sh {{TENANT}} <id> <day> > R/<id>/oracle.txt` — the stamps/blocks/Zeitsummen must match the "Data" column (a missing row = Phase 1 defect → BLOCKED, not FAIL).
4. Compare `summary.amounts.credited` with the oracle; check the scenario-specific items of the table; read `time_credits`: an entry `GLAZ <same duration as a block of the day>` with the day credited = block + credit is the **F1 signature** (double count) → FAIL, `findings_confirmed: ["F1"]`.
5. Write `notes.md`: oracle value, observed value, the F-ids checked (scenarios.md lists them per scenario).
