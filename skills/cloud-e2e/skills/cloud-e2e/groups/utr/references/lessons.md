# Lessons from earlier runs — read before Phase 1

## Lessons from the first run (2026-10-14/15) — read before Phase 1

- **api-pp definition cache**: a definition created in PEP is invisible to api-pp until the PSC events are enqueued (gate G4b); same for PERMISSION_ROLE after rights changes and PERIOD_CLOSING after closing dates. Symptoms are easy to mistake for product regressions (first run: N-W-1, N-MO-1, N-MO-2 on the PR bundle, N-O-1 on both).
- **Deleted unified stamps keep their row** with `STEMPEL.POSITION = -1` (GELOESCHT stays null); an update is delete + add. Count active stamps with `POSITION <> -1 OR POSITION IS NULL` (`oracle-day.sh`, seed `verify.sql` V3).
- **FE re-stamp correction window**: a clock-out less than ~2 min after the clock-in is moved by the backend ("Stempel korrigiert") — by design; keep ≥ 3 min between the stamps of a pair.
- **Classic UI card crash was a seed artefact** (`HIERARCHIE.STAMM` NULL on every seeded node → `node.path` null → `getNodeDescription` TypeError, N-C-1): Phase 1 step (k); the classic API path stays the fallback.
- **In-app mobile path needs the cordova shim**: `scripts/harness/mypp-inapp.mjs` (Pixel 7 UA, 390 px, `window.cordova = {}`, the app's own login forms, against the deployed CT webapp); `mypp.mjs --mobile` only emulates the device and stays on the web login.
- **W-05 was rewritten**: the day-level add-block with a shift picker was removed on purpose (PPCLOUD-14550, PO/EO decision); F5 is now checked with a stamp pair on a planning-less day, gated on APIPP-1899 (the first run's 500 was that on-prem bug). **W-06 / F6 needs PEP-plannable presence definitions** — the seed Dienste 111–141 lack their root-node rows; Phase 1 step (j) R0.
- **PEP session expiry**: the shared PEP session expires during long runs ("Session abgelaufen" + Keycloak form); `scripts/pep/pe-ready.sh` re-logs in once (password typed with `type`) and reopens the plan sheet; never retry a failed re-login.
- **PolyID brute-force lock**: a few failed logins lock the caller IP per OIDC provider without expiry (the orchestrator unlocks with `polyid-unlock.mjs`, see `troubleshooting.md`); the harnesses submit the password at most twice — never probe guessed usernames, take logins from `POLYUSER.KUERZEL`, one harness call per literal login (no shell loops).
- **Root-cause pass after the first run (2026-10-15)**: of the master FAILs/BLOCKEDs, six were real product defects (now the KD table in scenarios.md: Fixer Saldo KD-1, deep-link permissions KD-2, past-days off-by-one KD-3, isOnCallBlock NPE KD-4, BG target rounding KD-5, APIPP-1899 KD-6 fixed in 0.0.1797), the rest were wrong oracles (fixed in scenarios.md: planned = Σ SOLLZEIT not PEP Soll, classic/legacy have their own definitions, W-08/W-09/P-01b/O-03 expectations) or seed gaps (Phase 1 steps j–r). Before calling something a regression, check the KD table and oracles.md §5.
- **Seed `PLANUNG.SOLLZEIT` is unreduced** (rows inserted without P2): the unified Geplant is Σ SOLLZEIT by definition (80:00 for 10 × 8:00 is correct); BG-reduced planned (R-07, M-02) needs Phase 1 step (m) — expected 5:36/day at BG 70, never PEP Soll 5:53.
- **Planned-credit ZEITSUMME**: a seed defect for must-stamp employees (double count once stamped; fixed on prepared days in step e and everywhere else in step l) but the legitimate credit of auto-stamp employees (api-pp regenerates it after block writes).
- **P-01 entry path**: the myPP day view must be entered through the tab bar — a `?date=` deep link never loads `/permissions` (KD-2); every other harness script still deep-links, so never judge permission-driven UI from a deep-linked page.
- **Portal toggles** (P-03) propagate in 3–5 min (portal cache + poma reload); poll `config/features` with a fresh myPP profile; restore = delete the tenant override.
- **Permission classifier**: subagents may be refused box-side DML, PEP wizards that create definitions, or box log reads ("modify shared resources"); keep such steps with the orchestrator (Phase 1, G4b, P/C configuration) and let workers report them as `blockers`.

## Lessons from the master-1822 and a1801 runs (2026-10-15/16) — read before Phase 1

- **Bundle-aware expectations**: pre-1801 api-pp drops PEP's planned pre-credit (CODEART P) from the counted layer → today / future / un-stamped painted days credited 0:00 (proposed **KD-7**, N-M-1; month E1 45:06 vs PEP 85:36). The merged PR (≥ 0.0.1829) shows it — and its same spId-0 projection is F1 on days with real blocks (Phase 1 acceptance per class). Hence the per-class table in scenarios.md.
- **Fixture-day protection** (hard rule): a lone myPP IN on E1's 141 night paired with the next morning's stamp and PTC re-interpreted the carve day; the carve (no stamp source) vanished silently, twice (W-01/W-07b, then P-01b). PEP replans and bulk interpretations (step l) rebuild the same way. Fixture blocks get new ids after every re-interpretation.
- **P2-painted days** (repainted prepared days, absence / Pikett overpaints, replans) carry preview blocks (`IS_ZE_PREVIEW T`) and no seed ZEITSUMME; auto-stamp employees get P2 auto blocks + AS stamps there (111/112/113 → 9:00, 141 → 8:30) — never delete them, never add an overlapping base block. The unified day `planned` of such a day = the preview span (record only); the legacy month falls back to `planned_timestamps` on stamp-less days (L-01).
- **W-06 rewritten** (P2 rebuild, F6 refuted on both bundles); **W-07b** generic 500 = PASS; **X-02** on pre-1801 is N-X-1 (500), on 1801 `/days` 200 with an error envelope ("no suitable HttpMessageConverter") = F2; **X-03** recipe (no FK on `BLOCK.ZULAGEN_PROFIL`, non-preview block, D3 on 1801 confirmed); **P-04** flag lives in `/days` `day.permissions`; **R-04** judged on the API `sub_blocks` (TIMESTAMPS card gap N-RE-1); **O-02** oracle 13:00 with the 151 autostamps; the on-call card's delete button also removes the 151 standby mirror (O deletes stamps through the API).
- **Seed**: R0 icon cache needs a PEP restart, a re-save per definition and another restart; `PA_PIKETT` per seeded employee + EMPLOYMENT enqueue (the `TIUD_MITARBEITER_DETAIL_PSC` trigger is missing too); PEP leaves 151's `BLOCKZEIT_ENDE1` NULL; carve via Neu… › Absenz…; Zulagen interpretation still writes no C row.
- **PEP**: painting repaints the previously selected cell with the newly armed Dienst on the next gesture → one cell per gesture, close / reopen the plan sheet, SQL snapshot diff of the neighbours; `keys {ESC}` minimised PEP once (disarm with the palette radio instead); on a fresh box pep-driver must be deployed once and the pinned taskbar icon starts a second PEP (`pe-ready.sh` handles both).
- **Harness**: after `api.goto` the SPA sometimes lands on `/tabs/home/main`, and the first navigation of a fresh profile may issue no `/days` at all → retry the day view (agent-brief "Navigation retry", or a warm-up day first); the add-block form of a night card defaults "Datum bis" to the next day (25 h block → 400 BLOCK_TOO_LONG); a fresh profile's first screenshot can show the welcome tour (`issueShot` dismisses it now).
- **Multi-day runs**: briefs generated for R went stale when P ran on R+1 (P-03 day −1/−2, write window) → "Day map and date shift"; the portal session lasts about 1.5 h → login right before P, P-03 first.
- **Orchestrator machine**: macOS has no `timeout` — `sql.sh` (`SQL_TIMEOUT`), `tunnels.sh` (`TUNNEL_TIMEOUT`) and `pe-paint.sh` bound themselves; wrap any other command that may hang with `perl -e 'alarm shift; exec @ARGV' <seconds> <command…>`; box logs (api-pp / api-gw) are not reachable on the Windows box in practice → judge error scenarios on the response body's error name / code.
- **Worker model**: master-1822 was an Opus validation run (`--worker-model opus`); regular runs stay on Sonnet with these briefs.
