# Environment plan — two DeployMate envs, windows, partition, schedule

Copy of the S1 synthesis `env-plan.md` (2026-10-23), kept here so every session reads the same window ids, classes, partition and schedule. Section numbers are the original ones (other files cite them: §3 windows and conflicts, §6 seed partition and common seed, §7 recommendation and schedule). "DS §n" = the verified DeployMate sharing facts (folded into the deploymate skill's `SKILL.md` "Shared env" section and `references/`); `groups.md` / `catalogue.json` = the synthesis files the group packages were built from. Changes to window ids or classes go through the orchestrator (frozen interface).

## 0. Recommendation in short

- **Two DeployMate environments on CT**, both owned by one env steward. They are created in one provisioning wave, because DeployMate allows 2 in flight per owner.
  - **DM-X "roster"** hosts `swap`, `booking`, `partner`, `hp`, `ts`.
  - **DM-Y "identity & config"** hosts `utr`, `planner`, `auth`, `ops`.
- **Two is the minimum:**
  - people: ≈ 77 needed (82 with optional actors) against a seed maximum of 50;
  - Gruppe shape: swap, planner and UTR each need a large or isolated Gruppe, and a seed has only 2 large ones;
  - incompatible tenant states: the timesheet flag vs the UTR month table, the LEGACY switch vs timesheet, the Sollplan gate vs UTR.
- **Two is safe:** every remaining conflict is either avoided by the split or serialised in a named window (§3). No window on one env pauses a group on the other env, except the stage-wide CT windows.
- **Schedule:** Day 0 afternoon steward bring-up, then 2 working days with **K = 4 people** (the steward also runs `utr`). K = 5 gives slack. K = 3 needs 2.5–3 days.
- **One more env** when UTR or timesheet needs another bundle, when the run must finish in one day, or when the seed shape check fails (§7.3).
- The shared-tenant group and the human group need no DeployMate env (§5).

## 3. Shared-state conflicts between groups

### 3.1 Window classes

| class        | meaning                                                                           | protocol                                                                                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HARD**     | nothing else runs on that tenant, except the families in the window's `exempt`    | `windows/<env>~tenantcfg` state `requested → draining → active → released`. It becomes active only when every other runner reports `activeWorkers[env] = 0`; restore and prove the restore before release |
| **LOGIN**    | no fresh PolyID password login on the tenant; running sessions continue           | runners do not start new workers whose first step is a login                                                                                                                                              |
| **FLAG**     | a tenant flag differs from the baseline; only the listed groups or families pause | the other groups continue. Duration includes 2 × 5 min propagation (portal cache ≈ 3 min + POMA reload 60 s, `AbstractFeaturesService.java:90`)                                                           |
| **SOFT**     | visible side effect only (banner)                                                 | no new myPP layout assertion starts                                                                                                                                                                       |
| **INTERNAL** | affects only the owning group on that env                                         | the owning runner coordinates inside the group                                                                                                                                                            |
| **LOCK**     | a box resource: the PEP desktop                                                   | `locks/<env>~pep`, create-if-absent, ≤ 20 min, renew, takeover only after expiry                                                                                                                          |
| **JOBS**     | tenant-scoped POMA job, which acts on every employee of the tenant                | one job at a time per tenant, always `tenantIds=<env>`                                                                                                                                                    |
| **STAGE**    | CT-wide (one CT deployment for every tenant)                                      | `windows/ct~<id>` + the user's OK (standing since 2026-10-27; no announcement)                                                                                                                            |
| **SHARED**   | a shared tenant that is not ours                                                  | the owners' consent, announced, restored                                                                                                                                                                  |

### 7.3 When one more environment is needed

1. **UTR needs another bundle** (a PR pin, an older master build, or `--compare`): UTR gets its own env (UTR's own version gates), and Y keeps planner, auth and ops.
2. **Timesheet must be verified on a build with APIPP-1808 + the api-gw `mock` switch** (not on master yet): `ts` gets its own env pinned to that build. Otherwise HPN-19 = KNOWN-FAIL HPN-K1 / BLOCKED.
3. **The full run must finish in one working day:** go to B3 (split X into swap + hp + ts and booking + partner) with K = 6–7 and a second provisioning wave on Day 0.
4. **The seed shape check fails at S1 step 1:** e.g. no Gruppe gives swap 10 people of one roster, or Medizin cannot give planner 12. The affected group moves to a third env.
5. **An env breaks mid-run** (DM-213 relapse, box dead): the steward creates a replacement (≈ 1.5 h + S1 ≈ 2.5 h). If X is replaced, a **new** run partner is needed (an edit would wipe the log), and the partner readers re-run.

Not reasons for another env: a failing G-SWP-EVT (box limitation, same everywhere), the PolyID IP lock (steward unlock), or a stage-wide window (shared by all envs anyway).

- PolyID unlocks; G4b refreshes on request; grants HARD windows.
- Daily pre-flight per env at 07:45: G0, auto-stop off, services, PEP up (`pe-ready.sh`), IP allowlist union, GLN set.
- The S-CT-\* window requests.
- Final consolidation; the TTL and destroy decision only on the user's word.

### 7.5 Cost

2 envs × 8.50 CHF × ≈ 3 days ≈ **51 CHF per full run**, plus ≈ 87 worker-hours of Sonnet time. Human attention: ≈ 4 people × 2 days, mostly supervision, sign-ins and approvals, compared with 8–15 person-days of manual clicking today.
