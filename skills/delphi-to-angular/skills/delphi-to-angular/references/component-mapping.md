# Component Mapping Reference

For PDX component recipes (full usage patterns, layout pitfalls, icon names, width-control rule), see [pdx-recipes.md](pdx-recipes.md). This file is the Delphi → Angular mapping table only.

## Layout

| Delphi VCL                                    | Angular                                                                                                           | Notes                                                                                                                                             |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Top-level `TForm` (f\*.pas)                   | Routed standalone component, body wrapped in `<pp-form>`                                                          | Use when the form is a navigable feature/screen. Add a lazy-loaded route and use the canonical `<pp-form>` scaffold — see angular-conventions.md. |
| Modal `TForm` from `ShowModal` / `CreateForm` | Angular dialog component opened via `MatDialog` / project dialog wrapper                                          | Do not add a route for modal-only forms. Generate a dialog component and wire it from the parent action that opened the Delphi form.              |
| `TFrame` (fr\*.pas)                           | Child component                                                                                                   | Reusable, data via `input()`. Typically lives inside a `<pp-form-section>` or `<pp-form-block>`                                                   |
| `TPanel`                                      | `<pp-form-block>` inside a form, otherwise `<div>` with Tailwind                                                  | Plain `<div>` only for non-form layout                                                                                                            |
| `TGroupBox`                                   | `<pp-expansion-panel-item>` inside a `<pp-expansion-panel>`; or `<fieldset>` for static, always-visible groupings | Use `<fieldset>` only when the group never collapses. Do **not** use `<mat-expansion-panel>` — see angular-conventions.md pp-expansion-panel.     |
| `TPageControl` + `TTabSheet`                  | `<pp-tab-group>` + `<pp-tab>`                                                                                     | Use `@pdx/pp-tab` `PPTabGroupComponent` + `PPTabComponent`. | `TRzSplitter`                                 | CSS grid or flexbox                                                                                               | No splitter component needed                                                                                                                      |
| `TShape`                                      | Tailwind border/divider utilities                                                                                 |                                                                                                                                                   |

| `TMemo`                                                                         | `<pp-textarea label="Label" [formField]="form.field" />`                                                                                   | Use `@pdx/pp-input` `PPTextareaComponent`. Implements `ControlValueAccessor`                                                                                                                                                                                                                                                |
| `TRadioGroup` styled as toggle buttons / `TSpeedButton` group with `GroupIndex` | `<pp-button-toggle-group [(selectedValue)]="value">` with child `<pp-button-toggle value="a">A</pp-button-toggle>` items                   | Use `@pdx/pp-button-toggle` `PPButtonToggleGroupComponent` + `PPButtonToggleComponent` for view-mode pickers, density toggles, and on-screen segmented filters. | `TECMonthEdit`                                                                  | `<pp-datepicker type="month-year" label="Period" [formControl]="control" />`                                                               | Use `@pdx/pp-datepicker` in `'month-year'` mode — user picks **only a month + year, no day** (panel walks them month → year). | `TPEPDateNavigator`                                                             | Custom date nav component (or `<pp-datepicker>` when only a single date pick is needed)                                                    | Custom for the prev/next month-stepper pattern. | `TTrackBar`                                                                     | `<pp-slider [min]="0" [max]="15" [ariaLabel]="'field' \| translate" [formControl]="control" />`                                            | Use `@pdx/pp-slider` `PPSliderComponent` (`ControlValueAccessor`, commits `number`). ### Icons

Use `@pdx/pp-icons` for all icons via `<span class="pp-icon pp-icon-<name>"></span>`. Icon names use **underscores** (`pp-icon-delete_trash`, `pp-icon-add`, `pp-icon-angle_right`) — never guess hyphenated names. The SCSS is global-only (`@use '@pdx/pp-icons/icons'` in the app's root `styles.scss`); never import it from a component SCSS file. See [pdx-recipes.md](pdx-recipes.md) for the correction table and scope rule.

### Shell-level components

`@pdx/pp-sidenav`, `@pdx/pp-top-navigation`, and `@pdx/pp-toolbar` (both `PPToolbarComponent` and `PPToolbarMobileComponent`) are app-shell components, **not** per-form primitives. A converted Delphi form is a feature routed _into_ the saas app's existing shell — it never introduces or replaces navigation or shell chrome.

Do not emit `<pp-sidenav>`, `<pp-top-navigation>`, `<pp-toolbar>`, or `<pp-toolbar-mobile>` markup from any conversion, even if the Delphi source has a `TMainMenu`, `TTreeView` used as a navigation tree, or a toolbar at the top of the form. Flag such elements in the conversion plan as "shell-level — leave to app-shell team" and move on.

Apply `pp-sidenav` in its default `'app-shell'` variant (and `pp-top-navigation` / `pp-toolbar` / `pp-toolbar-mobile`) only in a separate, explicit task that asks for app-shell work. Do not infer the need from screenshots or from a design that happens to show a bar / column — those may be page headers, filter panels, or inspector panes. For an in-feature drawer (filter panel, inspector pane, document outline) introduced by the conversion, use `<pp-sidenav variant="panel-only">` — it renders only the right-hand panel and is the PDX replacement for the old `mat-sidenav` drawer pattern.

## Events to Reactivity

| Delphi                       | Angular                                                                                                                                                                                                                      | Notes                                                                                                                                                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OnClick`                    | `(click)="method()"`                                                                                                                                                                                                         |                                                                                                                                                                                                                     |
| `OnChange` / `OnExit`        | Signal Forms `form.field().value()` or `(input)`                                                                                                                                                                             | Debounce where needed                                                                                                                                                                                               |
| `OnDblClick`                 | **Never `(dblclick)`** — explicit affordance instead: a dedicated action button (e.g. `pp-icon-button` per row), an entry in the row's `pp-menu` / `pp-table` row-actions menu, or single-click selection + a toolbar action | Double-click is a desktop-only idiom: it is undiscoverable on the web, unusable on touch devices, and invisible to screen readers. Promote the Delphi `OnDblClick` handler (usually open/edit) to a visible action. |
| `FormCreate`                 | `constructor()` or field initializers                                                                                                                                                                                        | Runs once at instance creation. Reserve `effect()` for input-driven re-runs (those map to `FormShow`).                                                                                                              |
| `FormShow`                   | `effect(() => store.load(this.id()))` reacting to inputs / route activation                                                                                                                                                  | Runs every time the form is brought to front in Delphi. The Angular analogue is an effect that reacts to `input()` signals or route params and triggers a store load.                                               |
| `FormDestroy`                | `DestroyRef` / `takeUntilDestroyed`                                                                                                                                                                                          |                                                                                                                                                                                                                     |
| `FormCloseQuery`             | `canDeactivate` guard or dialog confirm                                                                                                                                                                                      |                                                                                                                                                                                                                     |
| `SyncButtons` / `SyncLabels` | `computed()` signals                                                                                                                                                                                                         | Derived state, no manual sync                                                                                                                                                                                       |

## Naming Transform

1. Drop prefix: `f` (forms), `fr` (frames), `dm` (data modules)
2. Convert to kebab-case: `EditMitarbeiter` -> `edit-mitarbeiter`
3. Translate German to English: `edit-mitarbeiter` -> `edit-employee`
4. Component class: `EditEmployeeComponent`
5. Store class: `EditEmployeeStore`
6. Service class: `EditEmployeeService`
7. Property names: camelCase English (`nachname` -> `lastName`)
