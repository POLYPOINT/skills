# DeployMate — on-prem test environments on demand

DeployMate (repo `cloud/deploy-mate` on Azure DevOps, Jira project `DM`) provisions one Windows GCE VM per environment with Oracle, P2/PEP, the P4 APIs (api-pp, api-gw, …), Keycloak/IDM, Nomad/Consul and RabbitMQ, seeds test data, and registers the box as a tenant on a cloud stage. API: `https://deploymate-api.dev.k8s.polypoint-dev.com/api/v1`. SPA: `https://deploymate.dev.k8s.polypoint-dev.com/ops/`.

Files:

- `references/` — `api.md` (every endpoint, request and response fields, error codes); `environment.md` (FSM and durations, what runs on the box, DNS and ports, versions, cloud tenant, seeded data manifest, PR-env build mechanics).
- `scripts/` — `dm-login-capture.mjs` (one-time browser login → refresh-token file); `dm-open-spa.mjs` (reopen the SPA signed-in for the human to watch); `dm-api.sh` (CLI wrapper for the API); `dm-upgrade-stdin.ps1` + `dm-rerun-jobs.ps1` (DM-213 repair, copied to and run on the box, § 6a).
- `assets/` — `create-*.json` (create payload templates).

## Hard rules

- **Secrets never leave the credentials file.** Reveal responses (RDP, DB, PEP), tokens and the session file go to a 0600 file outside any repo, artifact, dashboard, brief or chat message. Print only the env id, host and username.
- **Destroy only when the user asks for that env by id.** `DELETE` is irreversible (VM, disks, DNS, firewall and the cloud tenant). Prefer `stop` or a shorter TTL when unsure. Never destroy an env you do not own or that was shared with you.
- **Spend consciously.** Default machine costs about CHF 8.50 per day; quota: 2 envs in flight per owner (DONE does not count), global ceiling 50 (effective = live vCPU headroom ÷ 4). Disable auto-stop only for the duration of a run; extend TTL in steps instead of asking for long-lived.
- **Every stage is a dev cloud** (CT, REVIEW, PREVIEW), never production. A customer-derived DB dump still holds real-looking data: do not export it or paste rows into shared places.
- **One env id, chosen once.** `^[a-z][a-z0-9-]{0,14}$`, max 15 chars (Oracle hostname). It is also the CT tenant id, the DNS label and the default email domain `<id>.ch`. Prefix with the purpose, e.g. `utr-p-1801`.
- **Do not work around the API.** No kubectl into the `deploymate` namespace, no reading its Secret Manager entries, no direct DB. Everything an engineer may do is an endpoint.

## 1. Get access (once per machine)

1. Check prerequisites: `curl -sf https://deploymate-api.dev.k8s.polypoint-dev.com/actuator/health` returns UP; `jq`, `node` available.
2. Capture a session (the human signs in; the SPA client allows only browser login + refresh tokens — password and device grants are disabled):
   ```bash
   mkdir -p ~/.config/deploymate && cd ~/.config/deploymate
   npm init -y >/dev/null && npm i playwright >/dev/null && npx playwright install chromium
   node <skill>/scripts/dm-login-capture.mjs ~/.config/deploymate/dm-session.json
   ```
   Run it from `~/.config/deploymate` (it resolves Playwright from the working directory). It opens Chromium on the SPA, ticks "Stay signed in on this device" (tick it yourself if it is not ticked - without it Keycloak issues no offline token and the session dies within hours), waits for the login, stores `{authority, client_id, refresh_token, sub, roles}` (0600) and prints the roles. Needs `ROLE_DEPLOY_MATE_USER` to create; `ROLE_DEPLOY_MATE_ADMIN` is read-only. Missing role → ask an admin to assign it in Keycloak realm polypoint-polyid-realm (`temp/kc-deploymate-roles.sh` in the repo).
3. Verify: `DM_SESSION=~/.config/deploymate/dm-session.json scripts/dm-api.sh me` prints the quota status and the caller IP DeployMate sees. Export `DM_SESSION` for the session.
4. Unattended alternative (CI, fleets): a confidential client with `client_credentials` in the same realm (`deploy-mate-automation`, `vinculum-fleet` exist; their secrets are in GCP Secret Manager, project ppcloud-dev — ask the owner, never read them on your own initiative). The API also needs the client in its `azp` allowlist.

## 3. Create and wait

1. Prepare the payload: copy a template, set `id`, `ipAllowlist` (`dm-api.sh my-ip` → `<ip>/32`; the API stores the list as sent and adds **no** office VPN range — only the SPA wizard pre-fills one — so every person who needs the box needs their own public `/32`; about 10 entries fit, Cloud Armor limit), `sshPublicKeys` (generate a dedicated key: `ssh-keygen -t ed25519 -f ~/.ssh/deploymate -N '' -C deploymate`), `ttlDays` (default 7, cap 30 from creation), `seedConfig` (`peopleCount` 1–50, `includeLoginUsers true` gives every person a Keycloak login with PEP + myPOLYPOINT roles on cloud-capable tracks), `emailDomain` if `<id>.ch` is not wanted.
2. Create: `dm-api.sh create payload.json` → 201 with the env; 400 `validation|invalid_pr_source|invalid_master_build_pin|invalid_db_dump|invalid_track|invalid_release_version` name the field; 429 `per_owner_cap|in_flight_cap` means wait (Retry-After) or destroy something.
3. Wait: `dm-api.sh wait <id>` polls every 60 s and prints state, retry count and last error. Typical path and p50 durations: `references/environment.md` §1. Budget ≈1.5 h for a plain env, ≈3 h with a PR pin, +1 h with a dump. Transient failures retry themselves (`nextAttemptAt`, `retryCount/retryLimit`); `ERROR` is terminal until `dm-api.sh retry <id>` (resumes from the failed state; a retry into `BUILDING_PR_ARTIFACTS` re-queues the CI build).
4. On failure read `dm-api.sh steps <id>` (one line per step with exit code) and `dm-api.sh logs <id> [afterId]` (cursor-paged lines; `--source ANSIBLE --step <name>` narrows). While a step is still running (`exit=-`) its `failed` status and `err=N` only count `fatal:` lines, which are often `...ignoring` cleanup tasks (killing orphaned PolyUpdate/PolyInst processes); the verdict is the exit code once the step ends. The long tail of INSTALLING_SOLUTION is the P2 PolyUpdate database step under a hang-watchdog (hard 2 h, stall 30 min).
5. Right after DONE: `dm-api.sh auto-stop <id> off` if the env must survive 19:00 Zurich (the VM's external IP changes on every stop/start), then consume the credentials into the credentials file (§4).

## 4. Use the environment

- **Addresses.** `<id>.deploymate.polypoint.dev` is the load-balancer name (TLS, wildcard cert); `<id>-host.deploymate.polypoint.dev` is the VM itself. Resolve the IP with `dig +short <id>-host.deploymate.polypoint.dev`. Firewall per env, from the allowlist only: 22 SSH, 1521 Oracle, 3389 RDP, 8383 Keycloak, 8443, 9090 Traefik (P4 APIs), 9091 Traefik API. IP changed? `dm-api.sh refresh-ip <id>` re-applies the firewall with the caller's current IP (`REAPPLYING_FIREWALL` → `DONE`): for the owner it **replaces** the allowlist (`replaceExisting: true`); on a shared env the owner uses `refresh-ip <id> --union`; an operator's call always adds its single `/32` (union).
- **Services.** `dm-api.sh services <id>` lists the registered P4 services and their path prefixes; the URL is `http://<id>-host.deploymate.polypoint.dev:9090<pathPrefix>` (swagger at `<…>/swagger-ui.html`). api-pp: `/pp-api-personnel-planning`, api-gw: `/pp-api-gateway` (its `GET /api/v1/polypoint-versions/current` shows the bundle version the cloud will see, e.g. `26.99.0 rev:<sha> nightly` on master).
- **Credentials** (one-shot reveal + consume, token valid 60 s, owner or OPERATOR share — 404 for viewers and everyone else, 409 `*_not_ready` before DONE; every reveal is audited with the consumer's sub): `dm-api.sh reveal <id> rdp > creds` (user `pp-01`), `dm-api.sh reveal <id> db > creds` (Oracle proxy login `VINCULUM_FLEET[ECBERN]`, host, port 1521, service `POLYP01`, ready JDBC URL — direct SQL on ECBERN from your machine), `dm-api.sh reveal <id> pep` (only for `PRESERVE_IDENTITIES` dump envs: the one password for all imported PEP users; `adminec` keeps the configurer superuser password).
- **SSH.** `ssh -i ~/.ssh/deploymate pp-01@<id>-host.deploymate.polypoint.dev`; keys (≤ 5 per env, owner only) are replaced with `dm-api.sh ssh-keys <id> <pubkey-file>` (PUT = the whole list) or appended with `dm-api.sh ssh-keys-add <id> <pubkey-file>` (`APPLYING_SSH_KEYS` → `DONE`).
- **PEP on the box.** Use the `pep-verify` skill with a synthesised inventory (`ansible_user=pp-01`, the RDP password); fresh boxes have no interactive session until the finalize reboot ran, see `references/environment.md` §7.
- **Seeded users and data.** `dm-api.sh test-data <id>` returns the manifest: `people[]` with `displayName`, `station`, `timeRecording` (`TIMESTAMPS` even index = must stamp, `BLOCKS` odd = auto-stamp), `pincode`, `login`; `loginUsers[]` with `username`, `polyuser`, `email`, `clientRoles` and the shared `loginPassword`; `orgUnits`, `shifts`, `roster` span, `licenses`. Badges are `DM<employee-id>`. Readable by the owner and by VIEWER / OPERATOR shares. `available=false, reason=DB_DUMP` on dump envs.
- **Cloud side.** The tenant id equals the env id, under org `deploymate-<owner>` on the stage's PolyPortal; PolyId 2FA off; users sign in as `<login>@<emailDomain>`. CT URLs: myPOLYPOINT `https://ct-poma-webapp.dev.k8s.polypoint-dev.com`, portal ops `https://ct-portal-webapp.dev.k8s.polypoint-dev.com`, Keycloak `https://ct-keycloak.dev.k8s.polypoint-dev.com` (REVIEW/PREVIEW follow the `<stage>-` pattern on ppcloud-demo). `dm-api.sh health <id>` shows the portal's view (vpn, ping, health, deephealthcheck, ratelimiter). Feature toggles set by DeployMate: `poma.mobileApp.timeRecording` on, `poma.mobileApp.unifiedTimeRecording` per mode, deep-health ignore for poly-time-connect.

### 6a. DM-213 repair (manual, until DeployMate fixes DM-213)

The repair needs the box's SYS login for one statement. It never passes through Claude Code: the operator types it into a terminal of their own, the box reads it from stdin, nothing stores it. Never write the SYS login, a connect string with credentials or a password into a file, a prompt, a brief or chat.

1. Detect: `dm-api.sh services <id>` lists only Traefik's internal routes (no `/pp-api-personnel-planning`, `/pp-api-gateway`), tenant health DOWN; over SSH `nomad job status` shows the P4 jobs dead.
2. Copy the two scripts to the box (Claude may do this; they hold no credentials):
   `scp -i ~/.ssh/deploymate <skill>/scripts/dm-upgrade-stdin.ps1 <skill>/scripts/dm-rerun-jobs.ps1 pp-01@<id>-host.deploymate.polypoint.dev:D:/TempPOLYPOINT/liquibase/`
3. The **operator**, in their OWN terminal window — not inside Claude Code and not with the `!` prefix, which gives the command no stdin (`read -s` then reads nothing and the script prints `NO_LOGIN_ON_STDIN`):
   ```bash
   read -s LOGIN      # paste the SYS connect string, Enter; nothing is echoed or stored in history
   printf '%s\n' "$LOGIN" | ssh -i ~/.ssh/deploymate pp-01@<id>-host.deploymate.polypoint.dev 'powershell -NoProfile -ExecutionPolicy RemoteSigned -File D:\TempPOLYPOINT\liquibase\dm-upgrade-stdin.ps1'
   unset LOGIN
   ```
   The connect string is EZConnect: `<sys user>/<password>@127.0.0.1:1521/POLYP01 as sysdba` (the CT SYS login of the DeployMate master image, from the operator's ansible CT vault). The alias form `…@POLYP01 as sysdba` fails with ORA-12154: new boxes have no `tnsnames.ora`. Check the host is the NEW box (shell history may offer an old one). Expected output: `INSTALLER_RESET_OK`, `UPGRADE_EXIT 0`, the Liquibase summary; `INSTALLER_RESET_FAILED` = nothing changed (check the string).
4. After the operator reports `UPGRADE_EXIT 0`, re-run the P4 jobs (Claude may run it):
   `ssh -i ~/.ssh/deploymate pp-01@<id>-host.deploymate.polypoint.dev 'powershell -NoProfile -ExecutionPolicy RemoteSigned -File D:\TempPOLYPOINT\liquibase\dm-rerun-jobs.ps1 api-pp-personnel-planning api-pc-patient-case id-administration-service api-gateway poly-time-connect'` → one `RUN <job> -> Evaluation ID …` line per job.
5. Verify within a few minutes: `dm-api.sh services <id>` lists the five P4 routes, `dm-api.sh health <id>` ping / health / vpn UP.

## 7. When the SPA is the better tool

To let the human watch: `cd ~/.config/deploymate && node <skill>/scripts/dm-open-spa.mjs /ops/envs/<id>` opens the SPA with the signed-in profile (stays open until the window is closed; the SPA and `dm-api.sh` share the offline token safely, but the SPA logout button ends the browser session).

Create wizard with live validation (`/ops/envs/new`), status page with FSM graph and live log tail, destroy modal, Tailscale enrolment with browser approval, admin fleet view, cost analytics and audit log. Everything else is scriptable; prefer the API for repeatability.

## 8. Shared env (one steward, several operators)

Used by the cloud-e2e skill; any team sharing one env follows the same rules.

- **One owner, no transfer.** The owner (steward) alone can create, retry, reseed, destroy, set SSH keys, auto-stop and the time-recording mode, and share / unshare. Keep the owner reachable during a run; a reseed renumbers every employee and Keycloak user (never during a run).
- **Sharing.** Each person captures their own session (§1) and sends their `userId` (`dm-api.sh me`). The owner runs `dm-api.sh share <id> <userId> OPERATOR` (reveals for themselves, `/32`, TTL, power) or `VIEWER` (read only, `test-data` included). No secret is ever pasted: each operator reveals into their own 0600 file.
- **Network budget.** About 10 allowlist entries per env (Cloud Armor; an 11th re-apply may fail quietly back to DONE): owner + ≈ 9 people, an office NAT counts once. Operators add their own `/32` (`refresh-ip <id>`, always union); the owner uses `refresh-ip <id> --union` so nobody is dropped.
- **SSH.** ≤ 5 keys per env, owner only: collect the **public** keys and `ssh-keys-add` them; never handle a private key.
- **PEP = one desktop per box.** PEP runs in `pp-01`'s single interactive session: serialise every PEP step (a lock), no human RDP while a pep-driver agent works. A second machine with SSH and the RDP password drives the same pep-driver agent (token read over SSH), no redeploy.
- **Reset.** No snapshot / restore: undo your own writes, or reseed / clone a template / destroy + create (owner).
- **Stage-wide state** on CT (gateway-mock strategies, untargeted POMA jobs, provider and partner registries, the Teams domain mapping) affects every tenant of the stage, other teams included: change it only in an announced window with the user's OK.
